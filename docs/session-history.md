# Session History

普通对话、主动表达、插件推理与插件表达共用每个 session 持久化的当前 History。
上下文包含宠物性格、静态快照、按发生时间排列的 History 及当前输入。
动态快照仍按原流程生成、更新和保存，但不再注入这些模型上下文。

## 单元与时间段

每条已对用户可见的消息、每个事件、每段非空影音总结各计一个单元。
助手消息按实际消费/播放进度保留可见内容，不把未播放文本写成已发生的对话。
普通 chunk 按 UTC 自然时间划分，每十分钟一段，使用半开区间。
消息与事件按发生时间入段，迟到的影音结果按采集时间入段。
模型输入保持平铺；内部来源 ID、计数和版本号不发送给模型。
共用来源说明明确 `as` 是宿主自动采集整屏画面与电脑播放声音形成的观察，
包含桌面操作与播放内容。它可直接支持近期活动回顾；旧回复及画面文字中的能力声明
不能覆盖本轮感知状态。该说明也用于插件上下文与 History 压缩。

```text
2026-09-18 08:00:00 UTC - 2026-09-18 08:30:00 UTC
summary: 用户和宠物聊起小时候看过的电影，随后一起看了预告片……

2026-09-18 08:30:00 UTC - 2026-09-18 08:40:00 UTC
u: 刚才那个人是不是之前出现过？
a: 看衣服像是同一个人。
as: 画面切回站台，先前的乘客拿着行李上车。
event: app.changed；应用：浏览器
```

原始 Messages/Observations 与当前上下文分开保存。迁移首次读取 session 时构建视图，
之后用数据库触发器的持久队列增量同步，重启不会重新展开已压缩或已过期的历史。
源记录被修正或删除时，相关摘要失效，重新使用该段仍存在的原文，避免继续引用错误事实。

## 压缩

`FISH_MEMORY_HISTORY_TOKEN_LIMIT` 默认 `20000`，即 n=20。仅计算 History 文本，
不计性格、静态快照、图片和当前输入的系统包装。沿用项目已有的本地 token 估算，
不绑定某个供应商的 tokenizer。

当 History 超过 nK：

1. 移除结束时间早于当前五小时前的 chunk。原文段与摘要段使用相同规则。
2. 若仍超过 n/2 K，从最早的完整 chunk 开始选取，直到未选取的 History 小于 n/2 K。
3. 将选中内容一起交给推理模型，生成连贯叙述，融合交流、影音和事件，最多 2000 token。
   同时设置供应商输出上限并校验结果；空、超限或截断结果不替换原文。
4. 用一个覆盖所选时间范围的摘要 chunk 原子替换这些 chunk。它继续参与以后相同的压缩。

超大的单个 chunk 可以压缩自身。压缩时不持有数据库锁；期间新增的单元保持原文，
编辑或删除导致版本改变则放弃旧结果。不同 session 隔离，同一 session 同时只有一个压缩任务。
模型失败保留原上下文，在后续更新/读取时再次尝试。

`FISH_MEMORY_HISTORY_TOKEN_RETAIN` 继续供旧消息窗口等内部消费者使用，省略时默认为 limit/2；
新的统一 History 压缩始终采用 n/2。原始存档和 Recall 索引不因上下文压缩而删除。

## 五秒影音与连续声源

原生采集持续运行，每秒一帧，通常每五秒输出一个音频窗口；聊天、事件及十分钟边界
可以提前切段。图片按音频的实际 `[startedAt, endedAt)` 选取，每段最多五帧。
音频继续通过本地 ASR/声纹链路处理，模型只接收同期转写与图片，不接收录音。
模型输入先放前文参考，再按时间顺序放上一时段图片、当前时段图片。
每张联系图紧前标注所属时段、完整时间范围及图内帧的相对秒数；上一时段只供比较。
`heard` 只出现在当前时段，并与当前图内的时间对齐，不能配到上一时段或重复总结旧图。

窗口变短不会重置声源跟踪。声纹滚动状态使用真实时间与采样偏移，支持两秒等提前切段。
每次影音总结还参考同一采集流、同一 session 最近的影音摘要和带声源标签的原话；
上段总结尚未返回时也能使用已完成的 ASR。参考范围有界，且不作为当前段新增事件重复记录。
声源标签是可修正的聚类线索，不等同于人物姓名；身份不明确时保留未知。

静音且完整采样的画面与上一窗口一致时，本地跳过模型；仍推进窗口和声源处理进度。
静音但像素变化时，同时提供上段图片供模型判断；宠物眨眼、光标闪烁等没有明显内容变化
必须让两个摘要都返回空字符串。静止、停留、没有操作、未检测到变化本身不构成记录，
也不能附加在其他有效摘要后面。两个摘要类别独立判断：有新对白而无电脑操作时，只保留
影音内容，活动摘要仍为空。非空转写不会因空视觉结论丢失。空结果不占 History 单元。

旧固定周期影音聚合调度已删除；桌面电脑操作记录改为逐事件入 History，生产路径不再调用
十分钟操作总结。旧摘要的存储格式、读取方法和旧桌面客户端接口保留兼容。

## 验证边界

测试覆盖真实 PostgreSQL 的队列、时间排序、递归压缩、五小时边界、会话隔离、并发追加、
源记录修正与失败回退，以及桌面重试、五帧配对、本地声纹时间轴和原生提前切段。
模型测试使用替身；真实影视中的人物归属质量、ASR 准确率和端到端延迟需在实际播放中验证。

2026-09-19 验证结果：Python 相关主回归 1301 项通过，后续上下文与关闭清理补充回归通过；
真实 PostgreSQL 集成 7 项、桌面相关 107 项、Swift 音频 32 项通过。Electron 编译及
所有改动源码的类型检查通过。

扩展运行 `tests/test_app.py` 时有 9 项既有失败，在改动前的 HEAD 中原样复现
（日志模块新增依赖与旧测试替身不匹配，以及旧路由清单断言）。Ruff 的剩余 3 项长行
均位于既有数据库迁移，同样在基线复现；本次新增/修改逻辑无新增诊断。
