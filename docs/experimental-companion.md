# 陪伴模式

设置 → 陪伴 → **陪伴模式**。可配置空闲唤醒间隔（默认 5 秒）。默认关闭；关闭时普通聊天继续使用原有 R/W/H/T 并发路由。陪伴模式不提供 H 通道。

下文的「Jev」指陪伴的判断器。Jev 是可选的：填了 Jev API Key（设置里标为「可选 · 效果更好」）就用 Jev；没填时由推理模型按同样的问题和 JSON Schema 作答（`ReasoningJudge`，关闭思考），`CompanionJudge` 每次调用按有没有 Key 选择。说话表情的面部打分只由 Jev 提供，没有 Jev 时不生效。

## 决策与执行

- 用户语音预调用和文字输入：基于同一份冻结上下文，并行启动 Jev 与可用的 S/R/W/T 候选生成。末尾用户输入按已说完处理，实际语音结束和文本版本确认仍由原有语音协议决定。
- 候选通道已假定被选中，只生成 `m/a/e` 或 `m/a/q/e`，不再输出是否需要 Recall、搜索或 Task 的判断。
- S 结合当前语境和 History 自然接话；即使表达相近的意思，也使用贴合当前语境的自然表达，避免原句重复。
- Jev 选中后只采用该候选；未选候选取消。用户输入正式提交以前，所有输出保持私有，不启动工具、不写入正式 History、不播放。
- R/W/T 都先有浅回答。R 执行 Recall 后，由推理模型围绕原问题生成必要信息总结。W 走既有搜索能力；T 使用已配置的外部 Agent 及其现有可用性限制。一般模型能完成的回答、整理、比较和推理选 S。
- 工具实际执行前先写入自然语言开始事件，例如 `event: 关于“演员是谁”的搜索已开始，正在等待结果。`。它与浅回答一起进入原 session 的 History，供后续定时或新事件判断了解已启动的查询；不添加单独的任务状态列表。
- R/W/T 工作与播放生命周期分开；停止或打断语音不会自动取消已经提交的研究。结果完成后产生自然语言事件，原始 Recall JSON 不进入 History。
- 极长的 W/T 结果超过事件存储预算时，也会先整理必要信息；原始提供方响应/Agent 结果仍留在既有调用日志或任务记录中。
- 结果事件时间是最终结果准备完成的时间；Recall 包括问题摘要生成时间。事件带原问题和结果，进入原 session 的时间 chunk。
- 开始、完成、失败和本次结果等待中止各自记录实际发生时间。关闭运行时会记录本次等待中止；这不代表已经提交给外部 Agent 的任务也被停止。

## 事件与空闲唤醒

History 的新 `event`、非空 `as` 在写入后提供一次行为判断机会。宠物自身 `a` 和自己启动工具的开始事件不触发判断；用户 `u` 由输入通道处理一次，不通过 History 再次触发。开始事件仍保留在时间线中，后续结果事件仍有正常的单次触发机会。Codex 完成通知在实验模式先成为事件，不直接生成播报。

忙碌时事件仍然保存，但跳过本次行为判断。没有待处理队列；播完或打断完成不会补跑事件，也不会补跑错过的计时。History 异步物化保留内部接收时间，避免忙碌期间收到的事件因延迟物化而在播完后触发。

活跃 session 空闲、距上次行为判断达到配置间隔时，定时读取当前完整上下文判断。它可以自然延续尚未结束的聊天/主持，回应尚未回应的结果，或 wait。定时唤醒本身不写 History。语音关闭时，桌面消息订阅仍可维持实验模式的 session 绑定。

影音总结完成后另用 Jev `noul` 判断是否包含有效新增观察，通过才进入 History。纯自身语音/聊天回流、重复画面和微小宠物动作应被过滤。这个感知筛选可在忙碌时运行；忙碌时跳过的是 `next_action`。空摘要不调用筛选。模型判断仍可能误判，需要用连续实际场景评估。

## 上下文与播放

继续使用人格、静态快照、统一时间 History 和实时环境感知说明，不恢复 dynamic_snap，不添加意图或关注列表。正在运行的请求句柄、播放拥有者、输入版本仅是程序执行状态。

用户随时可以打断语音。原有设备播放消费位置决定历史截断，实验上下文显示为 `a: 已实际说出的部分(被打断)`，不会包含尚未播放的后缀或进度数字。后台结果仍可独立完成并入库。

Jev 接收文本；实验 S/R/T/W 请求附带最近 5 秒、每秒最多一帧的屏幕合成图，复用影音总结的时间顺序布局，注明时间范围和最近画面。语音和文字的同一版预输入共享一张冻结合成图，合图与 Jev 并行；自主事件和定时唤醒在 Jev 选中通道后读取最新画面，wait 不合图。图像以高细节发送；缺帧时使用实际帧数，连续相同画面沿用合并规则，不伪造缺失画面。感知关闭、模型不支持图片或最近 5 秒无可用帧时不附图。

Jev 和候选属于同一版预输入，转写变化或实验配置切换会撤销旧准备。关闭实验模式会撤销它的待表达内容，恢复原聊天路由。普通聊天的图片输入和通道规则保持不变。

仅开启屏幕感知时也保留最近五帧的有界内存缓存；沿用现有每秒截图，不增加采集频率。影音感知原有的语音阶段帧缓存期限保持不变。

## 实现与验证

`src/fish_memory/experimental/` 包含独立 HTTP 决策适配、通道生成、私有预调用、后台执行和单次事件运行时。复用现有 `PromotableAnswerSink`、播放回执、Recall、搜索、Agent 执行器及 Session History。未引入第三方 agent runtime 或新的注意力/规划状态。

协议参考 [TypeSafe API](https://docs.typesafe.ai/api)。默认固定 `jev-1.13.0`，可在设置中改为其他受支持版本。实际请求、响应和概率通过现有日志记录，类型为 `experimental.jev.decision`（推理模型代答时为 `experimental.judge.*`）、`experimental.jev.observation`、`experimental.channel.*`、`experimental.recall.summary` 等；授权头和 API Key 不写入日志。

并行能隐藏部分 Jev 耗时，不保证零延迟增长或更高准确率；模型等待取决于 Jev 和选中候选中较慢的一项。Recall 总结额外耗时影响结果事件出现时间，不必阻塞浅回答。

自动化覆盖候选并发与取消、提交前无工具执行、普通模式回归、忙碌事件不补跑、延迟物化不补跑、空闲唤醒、播放消费、影音入场筛选、Recall 总结与完成时间、外部 Agent 结果回流、配置与凭据隔离、数据库时间线与宿主事件幂等性。真实中文行为准确率、实际设备播放和外部 Agent 端到端任务仍需在启用实验模式后验证。
