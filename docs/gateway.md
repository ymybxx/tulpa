# 外部消息（网关）

让脚本、快捷指令、智能家居自动化、CI 等其他程序给 TA 发消息。在 设置 › 扩展 › 外部消息 打开后，桌面端在固定端口（默认 `17821`）监听所有网卡；只有带正确钥匙的请求会被接收。

## 发送

```bash
curl -X POST http://127.0.0.1:17821/events \
  -H "Authorization: Bearer <钥匙>" \
  -H "Content-Type: application/json" \
  -d '{"source":"快递柜","title":"取件提醒","text":"快递在 3 号柜，取件码 5821"}'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 内容，最长 8000 字 |
| `source` | 否 | 谁发的，最长 60 字；不填时为「外部程序」 |
| `title` | 否 | 标题，最长 200 字 |
| `speak` | 否 | 默认 `true`：这条是给用户的。主动陪伴关着时，TA 像对待自己查到的结果一样，经过同一套判断和多通道（说话、回忆、搜索、任务）来回应；主动陪伴开着时，它不单独叫醒 TA，TA 在正常唤醒时看到。`false`：只记进 TA 的上下文，之后聊天时 TA 知道 |
| `id` | 否 | 发送方自己的事件 ID。同一 `source` 下重复发送同一 `id` 视为同一条，不会重复说 |

不接受其他字段。事件发给当前角色的最新会话。

## 返回

| 状态 | 含义 |
| --- | --- |
| `202` | 已收下，`{"accepted": true, "id": "..."}` |
| `400` | JSON 无效或字段不对，`detail` 里有原因 |
| `401` | 钥匙不对 |
| `404` / `405` | 只接收 `POST /events` |
| `409` | 还没有角色 |
| `413` | 内容超过 64 KB |
| `415` | 需要 `Content-Type: application/json` |
| `429` | 所有持钥匙的发送方合计每分钟超过 60 条 |
| `503` | 本地服务不在线 |

收下即返回，不等 TA 回应。

## 安全

- 钥匙是 32 字节随机值，保存在用户数据目录的 `gateway-key`（权限 600），可以在设置里「换一把」；换了之后，旧钥匙立刻失效。
- 监听所有网卡，所以同一网络的设备带上钥匙也能发。设置里只列出其他设备能访问到的地址（192.168/10/172.16–31 私有网段和 100.64/10），不列代理软件的虚拟网卡地址。
- 发来的 `source`、`title`、`text` 和其他外部事件一样，只是外部内容，不当作主人或系统的指令。
- 本地服务的其余接口不对外；网关只转发这一种事件，并使用 App 的内部钥匙，不暴露它。

## 实现

- 桌面端 `electron/gateway-server.ts`：监听、鉴权、限速、大小限制，转发到本地服务的 `POST /internal/gateway/events`。
- 本地服务 `fish_memory/gateway/`：校验字段，把事件作为宿主事件（`external.message`）记入会话历史，和其他事件一样出现在 TA 的上下文里。事件不单独叫醒 TA（`wakes: false`）；`speak: true` 的事件标记为给用户的（`reports_work`），主动陪伴关着时由 TA 回应，和它自己查到的结果走同一条路。
