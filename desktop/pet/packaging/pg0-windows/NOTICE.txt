Modifications: embed a UTF-8 activeCodePage manifest into PostgreSQL executables,
preserving original manifests; accept verified build-time archives; allow the
application to select a private pg0 cache using the absolute TULPA_PG0_HOME.
Without TULPA_PG0_HOME, pg0 retains its original home-directory behavior.
On Windows, explicit TULPA_PG0_DEBUG=1 enables command/embedded debug logging
for the disposable CI package doctor; normal log levels remain unchanged.
Tracing writes to stderr so the Python SDK preserves failure diagnostics.
The Windows pg0 process restores the standard DLL search with
SetDllDirectoryW(NULL) before starting PostgreSQL; failures stop startup.
This isolates external-program loading from the frozen Python DLL directory
without changing the parent process. Non-Windows startup is unchanged.
Reference: https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application
Pinned input URLs and SHA256 digests are in sources.json. The Rust dependency
versions are fixed by the upstream Cargo.lock and cargo build --locked.
